# graph-influence-go

本地运行的图影响传播模拟与种子集合选取库。无任何外部服务依赖：所有蒙特卡洛模拟、
估计、选种与持久化都在进程内完成。

## 快速使用

```go
svc, _ := influence.NewService("./data")
defer svc.Close()

svc.AddNode("a")
svc.AddNode("b")
svc.AddEdge("a", "b", 0.4)

id, _ := svc.SubmitEstimation(influence.EstimateConfig{
    Model:      influence.ModelConfig{Model: influence.ModelIndependentCascade, UseEdgeWeights: true},
    Seeds:      []influence.NodeID{"a"},
    Rounds:     10000,
    BatchSize:  100,
    Seed:       42,
    Confidence: 0.95,
})
state, _ := svc.WaitTask(context.Background(), id)
fmt.Println(state.Estimate.Mean, state.Estimate.MarginOfError)
```

进程重启后，`NewService` 恢复图与任务记录；调用 `ResumePending()` 继续尚未完成
的任务。每个被恢复的任务都会按提交时记录的图内容哈希重新绑定到当时的图快照
（见「图绑定语义」），停机期间的图修改不会影响其结果。已完成、失败或已取消的
任务不会被自动重启。

## 传播模型

### 独立级联（Independent Cascade）

- 每个节点被激活时，对每条出边尝试激活其邻居，且**只尝试一次**。
- 尝试成功的概率即该边的传播概率：
  - `UseEdgeWeights=true`：使用边权重（需在 `[0,1]`）；
  - `UseEdgeWeights=false`：所有边统一使用 `DefaultProbability`。
- 传播按波次进行，直到没有新节点被激活。结果包含初始种子。

### 线性阈值（Linear Threshold）

- 每个节点有一个阈值；当所有**已激活入邻居**的权重之和达到阈值时，节点在本轮激活。
- 阈值来源：
  - `Thresholds[node]` 显式指定时使用该固定阈值（需在 `[0,1]`）；
  - 未指定的节点在每轮模拟开始时独立抽取一个 `[0,1]` 均匀随机阈值。
- 同步迭代直到达到不动点。边权重为影响权重，节点所有权重之和是否归一化由调用方负责。

## 参数

| 参数 | 含义 |
| --- | --- |
| `Rounds` | 蒙特卡洛模拟轮数，必须为正。 |
| `BatchSize` | 每个持久化批次包含的轮数，必须为正。 |
| `Seed` | 主随机种子，`int64`。 |
| `Confidence` | 置信区间置信度，取开区间 `(0,1)`，如 `0.95`。 |
| `K`（选种） | 预算：要选取的种子数量。 |
| `Candidates` | 候选节点集合；为空使用全部节点。 |

估计结果 `EstimateResult` 给出样本均值 `Mean`、样本标准差 `StdDev`、正态近似的
误差边界 `MarginOfError` 以及 `LowerBound` / `UpperBound`。

## 确定性保证

相同图、相同配置（含 `Seed`）下，无论是否并发、无论进程重启多少次，结果**逐位一致**：

- 每个传播决策（一条边的激活尝试、一个节点的阈值）都由 `(主种子, 批次, 轮次,
  边端点/节点)` 通过 SHA-256 域分离派生独立密钥，再由 ChaCha8 产生随机数；
- 随机数不依赖节点被遍历到的先后，也不依赖其他节点是否激活；
- 种子集合与候选集合都会去重并排序，节点遍历顺序固定为排序后的邻接表；
- 批次在任务内全局编号，不同估计规格（模型 + 种子集合 + 阈值覆盖）永不共享随机流；
  相同规格的批次会被 CELF 选种复用且不重复计算。

## 种子选取

使用 CELF（Cost-Effective Lazy Forward）懒贪心：依据每次选择的**模拟边际增益**
`f(S∪{v}) − f(S)` 排序，边际增益完全由配置模型的蒙特卡洛估计给出，不使用度、
中心性等任何静态图指标。贪心理论保证对影响力最大化目标函数的 `(1−1/e)` 近似。
候选按 ID 排序并使用确定性的平局规则。

## 持久化与崩溃恢复

- 所有写入采用「临时文件 + fsync + 原子 rename」，崩溃只会看到完整文件或旧文件，
  不会出现半写入。
- 图保存在 `graphs/current.json`，任务保存在 `tasks/<id>.json`。
- 任务提交时，其绑定的图快照写入内容寻址存储 `graphs/snapshots/<graph_hash>.json`
  （以图内容哈希命名，相同内容只保存一份），且先于任务记录落盘，保证绑定内容
  总是可恢复。
- 每完成一个模拟批次就原子落盘一次，记录 `Sum` 与 `SumSq` 等聚合量，以及该批次
  所属图的内容哈希（`graph_hash`），作为复用时的来源校验。
- 恢复时已完成的批次从磁盘加载并直接复用，**不会重复计算**；任务从下一个批次继续。
- 用户显式取消的任务在重启后保持 `cancelled`；进程关闭（模拟崩溃）则把任务保留为
  非终态，等待 `ResumePending()` 继续。取消不会写入部分估计/选种结果。

## 图绑定语义

**绑定时机**：任务在提交（`SubmitEstimation` / `SubmitSelection`）时绑定当时的图
快照，绑定关系（`graph_version` + `graph_hash`）唯一确定且终身不变。提交与图更新
在同一把锁下串行化，因此并发提交与更新时绑定关系稳定、可解释：任务结果只取决于
绑定的图内容，与更新发生的先后顺序无关，同一任务的统计绝不跨越更新前后的两个图
内容。

**图标识**：`graph_hash` 是图**内容**（节点、边、权重）的哈希，不含版本计数。内容
相同而仅版本递增（如先加节点再删除）时哈希不变；内容有任何变化哈希即改变。
`graph_version` 是单调递增的计数器，只用于排序与解释，不参与身份判断。

**运行中与恢复时**：运行中的任务只读取绑定快照，在线增删节点/边、修改权重不会
影响它。进程重启后，`ResumePending()` 按任务记录的 `graph_hash` 从快照存储还原
绑定内容——即使停机期间图被修改，恢复后的结果也与未中断、未改图时**逐位一致**
（均值、标准差、误差边界、置信区间均相同）。新提交的任务总是绑定最新图；旧图
结论不会被静默当作新图结论（图哈希不同）。

**缓存失效规则**：

- 每个模拟批次都记录其所属图的内容哈希；恢复时只有哈希与绑定内容完全一致的批次
  才被复用。哈希不匹配的批次（来自其他图内容，或无来源信息的遗留批次）绝不静默
  混用：任务以 `ErrGraphStatsMismatch` 失败。
- 不同任务之间不共享批次；同一任务内相同估计规格（模型 + 种子集合 + 阈值覆盖）的
  批次会被 CELF 选种复用，不重复计算。
- 图内容相同而仅版本计数递增不影响复用：快照按内容寻址、批次按内容哈希校验，
  均不发生重复计算；相同图与相同配置下多次运行及重启后的结果逐位一致。
- 快照文件只增不删；`graphs/snapshots/` 随出现过的不同图内容数量增长，确认没有
  未完成任务引用后可手工清理。

**显式失败**：恢复时若无法还原任务绑定的图内容（快照文件丢失或损坏，且当前图的
内容哈希与绑定哈希不一致），任务以 `ErrGraphSnapshotUnavailable` 明确失败
（`TaskState.Error` 中包含该标识，可据此区分），不会静默改用当前图，也不会被
标记为已完成。升级前遗留的未完成任务记录（没有绑定快照、批次无来源信息）按同样
规则处理：记录可正常读取，但任务明确失败而不是静默恢复；已完成的旧任务记录不受
影响。

**配置项**：绑定与校验行为全自动，无新增配置项。相关的既有配置只有 `BatchSize`：
它决定持久化粒度，崩溃后最多重算一个尚未落盘的批次。

**验证方法**：

- 任务的 `GraphHash` / `GraphVersion` 始终等于提交时的绑定值；同一绑定关系重复
  执行（含重启续跑）结果逐位一致，可用两个同配置任务对比验证。
- 中断-改图-恢复、内容不变的版本递增、更新与运行并发、统计混用拒绝、绑定不可
  还原时的显式失败等场景由 `binding_test.go` 覆盖：
  `go test -run 'TestResume|TestMixed|TestUnrestorable|TestLegacy' -v .`。

## 非法输入

错误均为可区分的哨兵错误（可用 `errors.Is` 判断），并尽量附带 `NodeError` /
`EdgeError` / `ValueError` 上下文：

- 空图、空种子集；
- 传播概率或阈值越界；
- 边引用不存在的端点；
- 自环、重复节点/边、删除不存在的节点/边；
- 轮数、批大小、置信度、选种数量非法；候选引用不存在节点；
- 选种数量超过候选数量。

## 资源边界

- 模拟只保留集合与邻接遍历状态，批次只保留聚合和，运行内存不随 `Rounds` 增长；
- 任务通过 `context` 在批次与 CELF 评估边界检查取消；
- `Close()` 取消所有运行中任务并等待协程退出。
